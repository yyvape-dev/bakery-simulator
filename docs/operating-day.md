# MVP：営業状況の保存と1営業日の安定化

既存の家具配置・所持金と保存キー `bakery_web_v1` を維持し、v2でトップレベルに `saveVersion:2`、`sim` に営業状態を追加しました。来客処理の更新ではv3として`customer`も保存します。
現在はv4で日別の材料費・設備購入・返金・開始時所持金を追加し、v1〜v3も読み込みます。費用のない旧営業データは当日の利益を未確定とし、翌日から通常集計します。
以前のセーブに営業情報がない場合は、家具と所持金を引き継ぎ、Day 1・09:00・開店前から始めます。

## 保存する内容

営業日、開店前／営業中／営業終了の段階、営業の実行・一時停止状態、時刻、焼成の残り時間、焼き上がったパン、棚在庫、当日の売上・販売数・来客数、次の来客までの進行、前日の締め結果を保存します。
準備・補充・開店／停止・営業の1分進行・締め・家具編集の確定・初期化で保存し、ページを隠したり離れたりするときにも保存します。
ブラウザーが保存に失敗した場合は通知します。選択、ドラッグ候補、仮店主の座標は保存しません。来客の位置と段階はv3から保存します。

ブラウザーを閉じていた時間を自動進行には換算しません。非表示中の営業進行も止めます。営業中のセーブを読み込んだ場合は保存時刻から再開し、一時停止のセーブは停止したまま戻ります。

## 1日の流れ

1. 開店前09:00：1回30円・5個ずつ即時仕込み。完成品と棚在庫の合計が15個を超える注文は受け付けません。14個ある場合、次の5個は追加できません。
2. 開店：必要設備への通行を確認し、営業開始。焼成にはゲーム内25分必要です。一時停止中も営業中の段階を維持し、仕込みを即時完成にはしません。
3. 補充：完成品から棚へ移し、12個の棚容量を維持。移動後の在庫を保存します。
4. 18:00：自動で営業終了。開店・仕込み・補充はできず、締めを待ちます。18:00に完成する焼成は完成品として保存します。閉店までに完成しない新しい仕込みは受け付けず、材料費も引きません。
5. 締め：当日の売上・販売数・来客数・費用・所持金を保存し、収支ダイアログを表示して、翌日09:00・開店前へ移ります。売上・販売数・来客数と来客間隔をリセットし、所持金・家具・パン在庫は維持します。開店前の締めは受け付けず、連打で営業日が飛ばないようにします。
6. 翌日の開店前には売上欄に「前日売上」と利益を表示し、開店後は「本日売上」に戻します。売上欄をタップすると収支詳細を確認できます。

営業途中に早めに締めた場合も、支払った材料と未完成の焼成は失わせません。残り時間を翌日に持ち越し、次の営業開始後に続きを進めます。
初期化は確認後に、家具・所持金・営業状況すべてを新規状態へ戻します。

## 確認したケース

- 古い家具・所持金セーブの読み込みと、新しい形式への保存。
- 準備上限、材料費、補充、営業中／一時停止中／焼成途中／終了後／翌日の再読み込み。
- 焼成の二重完成・売上の二重加算が起きないこと。
- 09:00～18:00の1日：パン20個を販売し、売上2,400円。材料費120円、初期所持金2,970円から終了時5,250円。画面の売上は利益ではありません。
- 翌日の準備・販売を開始でき、前日の結果を変更しないこと。
- 閉店直前の注文、ちょうど閉店時刻に完成する注文、資金不足、締め連打、早締めでの焼成持ち越し。
- 非表示時に時間を進めず、退出時に進行を保存すること。
- 壊れたJSONや不正な営業数値でも操作できること。保存容量の不足を通知すること。
- 初期化の承認・キャンセル。390×844、320×568相当の表示。

スマホ実機は未検証です。操作はChromiumのスマホ相当環境で確認しています。
