## 実装済みと現行の挙動

- 家具6種、各4方向。店舗初期10×10。床材、仕切り壁、出入口、壁材、低い壁表示。開店前に幅／奥行を2マスずつ最大16×16まで拡張。費用・撤去返金・保存に接続。
- 店主とノアが家具・壁・他人物を避けて移動。通常担当と仕入れ／製造／陳列／会計の個別優先指示。現在の仕事を完了してから指示へ切替。
- 仕入れ30円／5個分、仕込み・運搬・25作業分の焼成・回収・陳列・客の予約と移動・スタッフの実会計・退店・日締め。開店前仕込み上限15個。棚は全体共有12個。製造材料は共通材料。
- 所持金、材料費、設備・内装・増築・開発費、返金、収支、日進行、自動／手動保存。閉店・締め・再開・途中セーブに対応。
- 通常画面、メニュー、設備詳細、スタッフ指示、商品開発・評価・飾り付け、経営収支、設定、インラインの床／壁／増築編集。メニューと店づくり中は営業と作業を一時停止。
- 仕事、製造、棚在庫、来客・会計の実状態ラベル。表示自体はゲームデータを書き換えない。
- 8レシピ：水／ミルク × 具材なし／バター／チョコ／チーズ。新規試作時のみ費用。味・香り・食感・見た目の評価。木のプレート／緑のクロス／花は一度購入すると再利用でき、評価と単価へ反映。
- 新規開発は即時登録・保存 →「新商品完成！」（短い画像登場演出）→ 飾り付け。実際のパンはスタッフの通常仕込み・焼成・陳列で作る。開発だけでパン在庫を追加しない。
- 販売商品変更は既存の棚・生地・焼成・運搬・客の予約商品を売り切ってから切替。待機中は次の製造を止め、回収・陳列・会計は続行。予約取消あり。客が棚で確保した単価を保存し、会計で再計算しない。定番は120円、商品ごとに変動。
- 商品のパン8／材料6／飾り3の計17点は厚塗り生成済み・公開済み。`assets/products/*.webp` と manifest、`assets/product-art.js` のパス・表示位置を使用。計543,888バイト。パンと皿は別レイヤー。なし記号と読込失敗時は元SVGを表示。

## キャラクターの技術仕様

`assets/characters/noah.webp`／`owner.webp` は768×1024、256×256のセル、3列×4行。列はidle／walkLeft／walkRight。dir 0〜3の行。

- dir0：ゲームY＋（正面左斜め）、dir1：X＋（正面右斜め）、dir2：Y−（背面右斜め）、dir3：X−（背面左斜め）。実コードと参照シートで方向を確認する。
- 接地アンカー `[128.00010681152344, 194.692138671875]`。
- 1マスX軸の投影 `[43.09983825683594, 23.273902893066406]`。
- フットプリント常に1×1。高さ・太さ・全体70〜130%で足元は維持。
- `index.html` の characterGeometry／characterSprite／drawCharacter／hitCharacter が共通設定とセル切出しを使用。`assets/characters/geometry.json` に同じ仕様がある。
- 元モデル：`tools/art/models/characters/noah.blend` と `owner.blend`。再制作：`tools/art/build_characters.py`、`pack_characters.py`、`tools/art/README.md`。

新チャットで同じ作業環境・ファイル・GitHub接続・権限設定が引き継がれる保証はない。ZIPを読み取るか最新リポジトリを取得してから作業。作業方針を毎回確認して止まるのではなく、依頼範囲の制作・デバッグ・コミット・push・公開確認まで自走する。権限や接続が実際に不足するときだけ理由を説明する。
