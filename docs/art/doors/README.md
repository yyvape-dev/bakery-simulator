# 扉3種類 × 4方向

2026-10-20。正面素材を壁面へ変形していた扉を、斜め見下ろしの方向別画像へ変更。木のガラス・セージ・アーチの各4方向、計12枚。単純な鏡像ではなく、正面と背面、縦壁と横壁を別セルで制作した。

[12枚の方向一覧と実際の入口](review/index.html)。画面の列は正面横壁、正面縦壁、背面横壁、背面縦壁。後ろ側では開いた扉の葉が開口の一部に重なる。通路は透過画像で、開閉シミュレーションや経路判定を追加しない。

- 外の入口は横壁の正面。3種類の設定を維持。
- 室内の出入口は壁の `axis` で縦横を判別し、奥の境界（`y=0`／`x=0`）では背面を選ぶ。設定の扉スタイルを共通で使う。
- 低い壁表示でも扉は通行可能な高さを保つ。選択枠・編集中の半透明を維持。
- 各セルの敷居2点と柱の高さを測定。`door-art.js` が敷居の両端を実際の壁の端点へ一致させる。方向を持った素材の厚み・開いた葉は保持し、投影の微差だけ補正する。
- 描画は状態を変更しない。壁・経路・占有・費用・保存形式は従来どおり。素材欠損時は既存の開口表示へ戻る。

生成元は `directional-atlas.png`（4列×3行、行の切出し境界は0／330／655／1024px）。元の扉アトラスを参照し、透明な開口、同じカメラ、方向別の開いた葉を指定した。再構築は `node tools/art/pack_doors.cjs`。実行時は `assets/doors/{timber,sage,arch}-r0..3.webp`、登録座標は `geometry.json` と `geometry.js`。`door-art.js` が読み込み・方向選択・描画を担当する。

検証：`node tools/tests/doors.cjs`（12画像の非空・透過・開口、12敷居の端点一致、4方向選択、状態非変更、3スタイル、保存、画像欠損時の代替）。既存 `interior.cjs` と `workflow.cjs` でも編集・営業を確認する。

回帰結果：内装23項目（増築後3日間を含む）、営業20項目／3日間が成功。売場と厨房をつなぐ出入口の通行、保存、費用・収支・在庫の整合を維持。
