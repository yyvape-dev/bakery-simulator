# MVP：来店 → 棚へ移動 → 購入 → 退店

来客発生時の即時購入をやめ、客が家具を避けて棚へ歩き、到着時に在庫・売上・所持金を更新する流れにしました。
新しいキャラクター素材は追加せず、仮表示の客1人を使用しています。

## 動作

- 入口は従来の到達判定と同じタイル(5,9)。入口の表示をその位置へ合わせ、入口マスを薄緑で表示します。
- 客は入口の外から入店。最短12ゲーム分の来客間隔で、店内に客がいる場合は次の入店を待ちます。進行中の客を新しい客で上書きしません。
- 家具の全占有マスを障害物にして、4近傍の幅優先探索で通行可能な最短経路を求めます。斜めに角を抜けたり、家具を通り抜けたりしません。
- 複数マス・90度回転した棚の周囲にある通行可能なマスを到着地点にします。MVPでは棚の正面だけには制限せず、周囲の空きマスで購入します。
- 最初に最も近い到達可能な棚を選び、各マスの到着時に経路を引き直します。棚の移動・撤去にも対応します。
- 棚の周囲へ実際に到着し、在庫があり、レジを利用できる場合に1個120円で購入します。購入した客はパンの印を付けて出口へ歩きます。
- 売り切れ、棚やレジが利用できない場合は購入せず退店します。MVPではレジまでの移動・会計待ちの行列は未実装です。

## 家具編集・一時停止・閉店

入口と客の現在のマス・通過中の次のマスへの家具配置は拒否します。将来の経路上への配置は、既存の衝突・通路分断判定を満たせば可能です。次のマス到着時に経路を再計算します。
一時停止・非表示中は客の移動と購入も停止し、再開後に続きを進めます。
18:00の自動閉店では未購入客を退店へ切り替え、購入はしません。営業終了状態でも退店の移動だけ続けます。
「締め」で翌日に進む場合は残っている客を退店扱いにし、未完了の購入は取り消します。確定済みの売上・在庫変更は保持します。

## 保存

保存キーと既存の店舗・営業情報を維持し、`saveVersion:3`で`customer`を追加しました。
現在は日別の収支を追加したv4で、来客情報を引き続き同じ形式で保存します。
客の段階、位置、現在のマス・次のマス、対象の棚ID、購入済みフラグ、営業日を保存します。
購入済みフラグ・退店段階と、在庫・売上・所持金は同じ保存データにまとめて書きます。読み込み後の退店で再び課金しません。
途中の移動は同じマス間の位置から続け、後続の経路は現在の家具配置から求めます。
v1・v2に客の情報がない場合は、既存の売上・所持金・在庫を維持して、進行中の客がいない状態として読み込みます。以前の即時購入をやり直しません。

## 確認

来店時に課金しないこと、家具を避ける直交移動、棚到着時の一度だけの購入、歩行途中・購入後・一時停止・閉店後の再読み込みを確認しました。
棚の移動と撤去、レジ撤去、売り切れ、客がいるマスへの家具移動拒否、回転した棚、最寄り棚の選択、入口を塞いだ旧セーブ、非表示時の保存、翌日開始と初期化を確認しました。
1日の販売数・在庫・所持金の整合も確認しています。売上は経路と補充タイミングにより変わり、固定の結果にはなりません。
検証例では5個×4回を製造して20個を販売、売上2,400円、材料費120円、所持金2,970円から5,250円。来客数は24人で、売り切れの客も含みます。
390×844、320×568のブラウザー相当環境で検証。スマホ実機は未検証です。

## 今回の範囲

実装したのは客1人の来店・棚への経路移動・購入・退店と保存です。
店主の移動・製造・補充は従来の仮処理のまま。ノア・ルーク、新しい歩行スプライト、複数客の行列、レジでの実際の会計行動、配置コンボは未実装です。日別の利益集計は基礎MVPの仕上げで追加済みです。
動線によって購入までの時間が変わる土台を、配置のパズル性へつなげる方針は `game-direction.md` に記録しています。
